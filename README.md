# 房仲買方工作台 v1

以買方需求為核心的無套件、純前端原型。所有內建資料均為虛構。無須 API 金鑰，不收集電話或地址，不將使用資料上傳 GitHub。

## 啟動

最簡單：下載 ZIP，解壓縮，在 Chrome / Edge 開啟 `index.html`。如瀏覽器限制 file:// 儲存，使用以下穩定方式：

1. 安裝 Python 3。
2. 在專案資料夾開啟終端機，執行 `python -m http.server 8000 --bind 127.0.0.1`（Windows 也可用 `py -m http.server 8000 --bind 127.0.0.1`）。
3. 用瀏覽器開啟 http://127.0.0.1:8000 。結束時在終端機按 Ctrl+C。

開啟位置、瀏覽器、裝置不同，各自是不同資料庫。請固定使用同一個網址與瀏覽器；無痕模式結束可能清除紀錄。

## 使用

- 買方需求：新增或修改區域、預算上限、總建坪下限、屋齡上限、車位、狀態、追蹤日期及其他條件。使用代稱，避免輸入真名。
- 房屋案件：管理區域、開價、總建坪、屋齡及車位。
- 帶看紀錄：先建立買方及案件，再選擇兩者、日期、輸入回饋。已被帶看引用的買方或案件不可直接刪除。
- 條件媒合：每項符合得 20%，依五項條件排序，逐項顯示符合與否。區域為精確文字比對，買方多區域可用頓號或逗號分隔。價格及屋齡不得超過上限，坪數不得低於下限，車位選「不限」不設限。100% 不是成交機率；格局、朝向等備註需人工核對。
- 待追蹤：台北日期當日及以前且非已成交／暫停的買方。
- CSV：各分頁分別匯入匯出。先匯出取得格式，同代碼更新、新代碼新增，無效資料整批拒絕。匯入順序：買方 → 案件 → 帶看。CSV 不會刪除原有列。
- 完整備份 JSON：含三種資料及關聯，可搬移到另一瀏覽器；還原會覆蓋全部資料，先備份現況。
- 手機：可透過手機鍵盤內建聽寫在備註／回饋輸入；本版本不包含語音辨識、自然語言需求擷取、ChatGPT、Excel 自動同步或跨裝置同步。

## 資料結構

`buyers`: id,name,district,budget,size,age,parking,status,next,notes

`properties`: id,name,district,price,size,age,parking,notes

`visits`: id,buyerId,propertyId,date,feedback

金額為萬元，面積為總建坪，屋齡為年。日期 YYYY-MM-DD。車位：平面車位／機械車位／無；買方另可不限。狀態：新需求／追蹤中／待帶看／議價中／已成交／暫停。

## 驗證及限制

有 Node.js 時執行 `node test.js`。測試涵蓋條件媒合、CSV 特殊字元往返、格式拒絕、重複代碼、負數、帶看關聯及試算表公式前綴防護。無外部依賴。

資料儲存於 localStorage，沒有登入、加密或雲端備份；限個人原型使用。公開倉庫只能提交程式與虛構範例，勿提交實際匯出、備份、姓名、電話、地址。匯出的 CSV 會為可能的公式字元加上單引號；因此此類自由文字重新匯入後可能多一個單引號。精確備份使用 JSON。

同一裝置請避免多分頁同時編輯，以免舊分頁覆蓋新資料。本原型不是完整 CRM 或外部 AI 服務；下一版可考慮登入、雲端資料庫、權限及經確認的語音結構化輸入。
