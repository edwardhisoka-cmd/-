# 張森焱 AI 工作台 · 屋主管理版（資料格式 v2）

沿用原有三模組、共用欄位／表單／卡片及媒合函式。新增屋主、共有人／聯絡窗口、委託、調價、追蹤與成交關聯。所有客戶、聯絡內容、財報及房屋均為示範資料，無真實個資、無外部 API、無付費套件、無公開部署。

本版新增 **Node.js 24 LTS 內建 HTTP／SQLite 服務**，提供真正的伺服器權限檢查。雙擊 HTML 只有唯讀示範，不能新增私人資料；正式操作請使用以下本機服務，不使用 Python 靜態伺服器。

## Windows 啟動

1. 安裝免費的 Node.js 24 LTS；確認 `node --version` 是 24 或以上支援 `node:sqlite` 的版本。無需 `npm install`。
2. 下載 GitHub 功能分支 ZIP，解壓縮，在 `workbench-mvp` 開啟 PowerShell。
3. 建立管理者（首次必做），密碼由終端機提示輸入、不顯示；至少 12 字元，沒有預設密碼：

   ```powershell
   node server.cjs --user admin --role admin
   ```

4. 可選：建立唯讀帳號（使用不同密碼）：

   ```powershell
   node server.cjs --user viewer --role viewer
   ```

5. 啟動並在網頁登入：

   ```powershell
   node server.cjs
   ```

   開啟 `http://127.0.0.1:8000`。Ctrl+C 結束。再次執行相同 `--user` 指令可重設密碼／角色；請先停止服務，重設後再啟動，以撤銷舊工作階段。

預設只綁定本機，不對外開放。資料統一保存在 `workbench-mvp/data/workbench.sqlite`（已 gitignore）；帳號密碼以 scrypt 雜湊，不儲存明文。需保留整個 data 資料夾，不能只重新解壓 ZIP 覆蓋資料。可使用 `--db <自訂路徑>`、`--port 8001`；建立帳號與啟動時需指定同一資料庫。

### 手機區網預覽

只使用示範資料時，在可信任私人 Wi-Fi 可執行：

```powershell
node server.cjs --host 0.0.0.0
```

用 `ipconfig` 找到 Windows Wi-Fi 的 IPv4，手機開啟 `http://該IPv4:8000` 並登入；防火牆僅允許私人網路。手機與電腦讀取同一個 SQLite，不再是兩份 localStorage。預設 HTTP 不加密傳輸，這個區網預覽不適合真實個資。未包含 HTTPS、公開託管或網際網路部署；本版未做上述設定。

## 已完成的屋主管理

- **基本資料**：屋主代稱、電話、Email、開發來源、開發日、出售意願、追蹤日與私人備註。
- **多對多關係**：`propertyOwners` 關聯既有屋主與物件，區分所有權人、共有人、代理人、聯絡窗口及持分。新增窗口不複製房屋。
- **去重**：物件有唯一 `assetKey`（自訂建物識別碼，英文字大小寫不影響去重），重複的同屋主／物件／角色也拒絕儲存。相同物件請重用識別碼；系統未串接地籍查詢，無法判斷不同代碼是否其實為同一建物。
- **委託**：一般／專任、起訖日、合約狀態、開價及底價。窗口必須已關聯該物件；同物件有效委託日期不可重疊，多位窗口由關係表維護。
- **調價**：編輯委託的開價／底價，自動追加不可直接編輯的歷史，並連動目前有效委託的物件開價。首次新增委託亦留下初始價格；調價日期依台北當日。委託的物件不可改綁，需另建新委託。
- **聯絡歷程**：聯絡、拜訪、委託洽談、帶看回報、追蹤；可記錄下次日期與待追蹤／已完成。帶看回報必須選擇同物件的既有帶看。總覽顯示屋主與未完成紀錄的到期提醒。
- **自動媒合**：沿用原有五條件，各占 20%；即時計算買方與具有效委託、未成交物件的配對，並顯示屋主／窗口。沒有有效委託、未開始、過期、終止、撤銷及已成交物件都不列入。媒合度不是成交機率。
- **成交**：成交物件、委託、買方、可選帶看、日期、實際成交價、實收佣金。跨表檢查同一物件／買方／委託日期；同一物件僅一筆成交。物件狀態由有效委託及成交推導，不再手動填寫。
- **統計**：開發聯絡人、具所有權關係的屋主、曾委託屋主、累計委託轉換率、去重物件、成交數、實際成交總額及佣金。轉換率分母為具有所有權人／共有人關係的屋主，分子為其物件曾有非撤銷委託的屋主；單純代理與窗口不計入。這是累計轉換率，尚非選定期間的同期漏斗。
- **搜尋與篩選**：自由文字（含關聯名稱）＋區域、最低／最高開價、出售意願及追蹤起訖日；條件以 AND 組合。屋主以其關聯物件篩選；追蹤日期包含屋主下次日期及未完成聯絡紀錄。完成紀錄的舊追蹤日不計入提醒，但屋主自己的下次日期須另行更新。

## 關聯資料模型（單一 SQLite 資料庫）

所有模組共用同一資料庫，沒有另外複製買方或房屋資料。SQLite 每種實體一張表，以 id 與 JSON payload 保存原架構；關聯欄位另外具有真實外鍵、延遲到交易提交時檢查。共用 `core.js` 的 fields／validate／prepare 同時供前端及伺服器使用。

```text
owners ──< propertyOwners >── properties ──< mandates ──< priceHistory
   │                              │           │
   └──< activities >───────────────┤           │
                    visits >──────┤           │
buyers ───────────────┘           └──< deals >─┘
   └───────────────────────────────────┘
```

| 資料表 | 主要關聯 |
| --- | --- |
| buyers | 原有買方需求，與 visits、deals 共用 id |
| owners | 屋主／權利人／窗口基本資料 |
| properties | 唯一物件、assetKey、行政區、road、基本條件；price 為有效委託開價的快取 |
| propertyOwners | propertyId → properties、ownerId → owners；role、share |
| mandates | propertyId、ownerId；type、start、end、status、asking、floor |
| priceHistory | mandateId、propertyId；date、asking、floor、reason（自動追加） |
| activities | ownerId、propertyId、可選 visitId；kind、date、next、status、notes |
| visits | buyerId、propertyId、可選 mandateId；date、feedback |
| deals | propertyId、mandateId、buyerId、可選 visitId；date、amount、commission |
| companies / financials / courses / sessions / questions | 原有投資、學習資料沿用，仍使用原關聯 |

每次儲存經共用驗證後，在一個 SQLite 交易內更新；revision 樂觀鎖拒絕另一分頁的舊版本覆寫，需按「重新載入」取得最新狀態再編輯。這是個人規模 MVP，尚非大量資料的分頁查詢系統。

## 權限與地址隱私

| 模式 | 可讀取 | 可寫入 |
| --- | --- | --- |
| 未登入／雙擊 HTML | 固定示範資料的公開投影 | 否 |
| viewer 唯讀帳號 | 伺服器提供的去識別物件／屋主關係、委託開價及統計；不回傳聯絡方式、底價、持分、私人備註、活動、買方帶看、個人投資／學習資料 | 否；直接呼叫 API 也拒絕 |
| admin 管理者 | 完整資料及私人備份 | 新增／編輯／刪除／還原；歷史由委託自動產生 |

- 私人資料不再寫進 localStorage。Cookie 是 HttpOnly、SameSite=Strict，工作階段 8 小時；登出立即撤銷。寫入檢查 Origin 與 CSRF token；5 次登入失敗暫停 60 秒。伺服器只提供白名單靜態檔案，資料庫及 server.cjs 不可經 HTTP 下載。
- **不收集完整門牌**：只填行政區與路名（可含段），拒絕巷弄、號、樓、室；對外物件名稱由區域與安全路名產生，不使用私人自訂名稱。對外摘要為嚴格欄位白名單，無聯絡資料、底價、備註、權利人姓名及完整門牌。請勿把地址或個資寫進公開行政區／路名欄位。
- SQLite 與完整 JSON 備份**尚未加密**；伺服器角色是應用程式權限，不限制電腦系統管理員直接讀磁碟。僅限示範使用；正式個資尚需 HTTPS、作業系統磁碟／備份保護及進一步安全審查。
- `audit` 只記錄寫入／還原時間、帳號、動作及 revision，不記錄私人內容。目前沒有稽核檢視 UI，也非防竄改的法遵稽核。
- 完整還原是管理者的明確覆蓋操作，會連歷史一起還原；一般寫入無法改寫既有調價歷史。沒有被其他資料引用的紀錄可刪除；委託已有歷史時請終止／撤銷，不可刪除而破壞關聯。

## v1 備份遷移

1. 先在舊版匯出完整 JSON 備份，保留原檔。
2. 在本版啟動服務、登入 admin，再「還原備份」。**會覆蓋目前三個模組，先備份現況。**
3. v1 → v2 保留買方、物件、帶看與投資／學習資料及原 id，補上物件 `LEGACY-原id` 識別碼。屋主、權利關係、委託與成交表先留空，不捏造關係或成交金額。
4. 舊版手動 stage 不再是資料來源；未補建有效委託／成交時，物件會顯示「開發中」且不參與自動配對。補建屋主 → 權利人關係 → 委託後即可操作。

舊版 localStorage `senyan-workbench-v1` 與根目錄房仲原版仍保留，這版不自動讀取或刪除；沒有 CSV 遷移。新版備份版本為 2，無效備份整批拒絕。

## 測試與驗收

```powershell
node test.js
node test-server.cjs
node ../test.js
```

- 21 組核心測試：原有估值／複習／資料驗證，加上多對多、去重、委託條件、調價連動、回報與成交一致性、配對排除、組合篩選、去重統計、地址限制、唯讀投影與 v1 遷移。
- 15 組伺服器測試：登入、密碼雜湊、敏感資料讀取權限、viewer 直接 API 拒絕、CSRF／跨來源、靜態檔白名單、SQLite 交易、版本衝突、關聯回滾、歷史不可竄改、備份還原、登出與重開持久化。
- 既有根目錄房仲測試仍通過。
- 開發時另以 Chromium 驗證：新增屋主、連結既有物件、調價、帶看回報、搜尋篩選、媒合、統計、公開摘要、登入／登出、唯讀權限、無 localStorage 私人資料，原有投資與學習功能回歸，以及 390px 房仲全部分頁無水平溢位。無 JavaScript 錯誤、無外部網路請求。未實機測試 Windows Edge／iOS Safari。

手動驗收建議：新增示範屋主 → 權利人與窗口連到 P001 → 委託管理修改 M1 開價與底價 → 查調價歷史與物件 → 聯絡與追蹤新增帶看回報關聯 V001 → 查需求配對及成交統計 → 登出，以 viewer 登入確認不能看到聯絡方式、底價或備份。

## 保留與尚未包含

原有投資研究、估值、課程、時間紀錄與間隔複習保留，改為由管理者登入後統一儲存於 SQLite。未串接 AI、外部行情／財報、地籍、簡訊、Email 或推播；提醒僅在開啟頁面時顯示。沒有多公司／團隊列級授權、附件、電子簽章或同物件重複轉售歷史。未購買服務、未合併 main、未公開部署。

沿用既有 `workbench-mvp/` 修改；根目錄原版買方工作台未更動。程式採 MIT，crm.js 沿用原專案程式。
